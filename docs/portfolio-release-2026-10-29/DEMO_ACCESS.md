# Открытый демо-доступ — обязательное правило

29 октября 2026 владелец потребовал показывать на карточках продуктов данные для входа под разными учебными пользователями: роль, логин, пароль, копирование каждого поля. Правило реализовано на RU/EN/RO и закреплено в AGENTS, PROJECT_GUIDE v3.13 и DESIGN_DOCUMENT §31.

**[Посмотреть карточки с доступом](http://127.0.0.1:4322/ru/portfolio/)**

## Что добавлено

- CRM Portfolio: администратор, руководитель и сотрудник — три опубликованных учебных аккаунта.
- Evo ERP: администратор, продажи, финансы, склад, проекты и аналитик — шесть учебных аккаунтов.
- Выпадающий выбор роли; логин и пароль видны открытым текстом в readonly-полях. Отдельные кнопки копируют каждое значение.
- Компонент есть в карточках главной и каталога, в ERP hero и прежнем блоке демо-доступа CRM. Клик по подписи, выбор роли и копирование внутри колоды не переворачивают карту.
- При отказе Clipboard API поле выделяется для ручного копирования. Устаревшее завершение копирования после смены роли/страницы не показывает ложный успех. Обработчики очищаются при Astro-навигации и pagehide, восстанавливаются при возврате из bfcache.
- Без JavaScript все аккаунты доступны через native details, значения можно выделить и скопировать вручную.

PDF сообщает, что ручные правки работают без аккаунта. Для Commerce, Founder и Recruiting показан текущий персональный вход ChatGPT: общего логина/пароля для него нет. Владелец отдельно откроет эти демо публично. Личные данные ChatGPT и owner keys не публикуются.

## Где поддерживать

`src/content/demo-access.ts` — единственный активный реестр опубликованных учебных аккаунтов, локализованных ролей и способов входа. Для каждого нового CatalogSlug необходимо явно выбрать режим. Режим `accounts` с пустым списком останавливает сборку.

`src/components/DemoAccess.astro`, `src/scripts/demo-access.ts`, `src/styles/demo-access.css` — общий компонент, поведение и оформление. CrmDemoAccess теперь использует его вместо отдельной реализации.

В реестр нельзя добавлять рабочие/личные аккаунты, значения `.env`, API-ключи, owner keys или провайдерские секреты. Новые пользователи должны быть прямо обозначены как общедоступные учебные в документации владельца.

- Внешние аккаунты, членство, пароли и бизнес-данные не менялись и не переинициализировались.
