## Lab performance and accessibility

The latest local mobile Lighthouse run in `artifacts/guidebook-2026-09-26/lighthouse-home-critical-problem.json` scored **Performance 97, Accessibility 100, Best Practices 100**. It measured **LCP 2.0 s**, **CLS 0**, and **total blocking time 130 ms**. Before the split, `lighthouse-home-responsive.json` scored 98/100/100 with LCP 2.0 s and blocking time 40 ms. Both exceed the plan's ≥90 performance target. Lighthouse accessibility scored **100 on all nine routes** before the split. Three repeated home → contact → home client-side cycles preserved the window state, restored the sticky header, raised no page error and kept document/window event-listener counts at 20/21. Local Chrome and WebKit tests do not replace physical Safari or representative field measurements.

The home CSS is now split from one source into about 14 KB of critical rules and 12 KB of remaining rules before compression. The first part is inlined; the second uses `media="print"` until its load event, with a `noscript` link for JavaScript-disabled browsers. The nine-route, 27-viewport checks pass after the split. A contact → home `ClientRouter` transition retained client state and loaded the deferred stylesheet. With JavaScript disabled, the recognition section and relay grid were styled and the 390 px viewport had no horizontal overflow. A 3-second artificial delay of the deferred CSS exposed a layout shift in the first section; moving that section's rules into the critical set removed it. `css-delivery-delay.json` records the same 1319 px height and relay grid before and after the delayed stylesheet loads. With the same delay, direct `#workflow` and `#approach` links on EN/RO/RU settle 96 px below the viewport top after the deferred CSS applies. Sections farther down the page remain subject to transient styling under extreme network delay.

**Field INP is unverified.** `node experiments/measure-interactions.mjs` exercised the mobile menu and workflow anchor on EN/RO/RU with 4× CPU throttling. The Event Timing API's largest observed interaction durations in `interaction-lab-final.json` were **72/64/56 ms**. These are lab proxies, not the site's future 75th-percentile field INP; the ≤200 ms target needs real traffic after release. The site remains a `noindex` prototype because the inquiry form has no delivery destination, the legal operator/privacy notice is not established, and the deep procurement demonstration has not been verified.

## Domain and publishing gates

`PUBLIC_SITE_URL` can be set to the confirmed production origin at build time. Astro then emits absolute EN/RO/RU `hreflang` links for each page. A test build with the reserved `https://example.test` origin produced all four expected alternates; the final build omits them because no production domain is confirmed. The prototype's current Lighthouse SEO score is **63**; `noindex` is the intentional remaining audit failure.

The plan mentions `magic`, `shadcn`, `node_repl`, Webflow and an Antigravity MCP configuration. On this Codex host those four MCP servers are already configured; the Antigravity file mentioned in the plan is absent. The suggested `modern-web-guidance-plugin` was not callable in this session, so the CSS and browser APIs above were implemented and checked directly. No React, Tailwind or additional runtime dependency was added.
