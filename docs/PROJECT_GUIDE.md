# Гид проекта Optimix

Версия 3.13 · 29 октября 2026 · действующий источник правил сайта.

## 1. Назначение и визуальный ориентир

Optimix автоматизирует бизнес-процессы: HR, документы, CRM, ERP, закупки, прогнозирование, аналитику и другие операции. Тематика компании не ограничивается закупками. Закупочный маршрут — один демонстрационный пример.

Владелец утвердил главную и потребовал довести сайт до уровня визуального макета. Затем он разрешил галерею шести демо-проектов и перенос **всех страниц и состояний** в этот дизайн. Действующий язык оформления с 29 октября: графитовый фон, бирюзовые акценты, светло-мятный текст акцентов, дополнительный оливково-зелёный, крупный Roboto, светлые интерфейсные превью и карточки, прежние радиусы и композиция. Палитра взята из двух изображений владельца в `docs/palette-2026-10-29/`. Прежняя концепция Operational Cinema больше не определяет дизайн сайта.

Источники: актуальные указания владельца → выбранные им изображения → этот гид и разделы 22–29 дизайн-документа → исследовательские референсы. После аннотаций владельца 13 октября главная переносит три примера процессов в hero и удаляет две повторяющиеся секции. Затем владелец заменил сетку пяти демо-модулей интерактивной колодой по предоставленному изображению; шестая All-in-one CRM остаётся широкой карточкой. Последующее изображение заменяет первый экран: CRM → аналитика, слои «Системы / Процессы / Люди», крупный двухцветный заголовок и светлый мятный фон. Заявки/документы и планирование остаются ниже первого экрана внутри hero. Остальная композиция и визуальная система утверждённых PNG сохранены; внутренние страницы используют ту же систему с композицией под свою функцию.

Макеты: `docs/redesign-2026-10-06/mockups/optimix-desktop-full.png`, `optimix-desktop-hero.png` и `optimix-mobile-full-board.png`. Мобильный board показывает три последовательных сегмента одной страницы. Детальный desktop hero сохраняет историческую спецификацию; для текущего первого экрана приоритет имеет изображение владельца из раздела 27. Растровые концепты не являются экспортом Figma: буквальное совпадение каждого пикселя не заявлено.

## 3. Маршруты и языки

Основные страницы: **51 маршрут**, по 17 в каждом языке. Дополнительно три страницы 404, всего сборка содержит **54 HTML-страницы**.

| Назначение | EN | RU / RO |
| --- | --- | --- |
| Главная | `/` | `/ru/`, `/ro/` |
| Бриф | `/contact/` | префикс языка + `contact/` |
| Конфиденциальность | `/privacy/` | префикс языка + `privacy/` |
| Проект | `/projects/procurement/` | тот же путь с префиксом языка |
| Каталог портфолио | `/portfolio/` | тот же путь с префиксом языка |
| Шесть продуктов | `/portfolio/{pdf-editor,erp,commerce,founder,recruiting,crm}/` | тот же путь с префиксом языка |
| Демо | `/demo/procurement/` | тот же путь с префиксом языка |
| Модули | `/solutions/{intake,budget,approval,erp,visibility}/` | тот же путь с префиксом языка |
| Ошибка | `/404.html` | `/ru/404/`, `/ro/404/` |

`pathFor`, `modulePath`, `demoPath`, `projectPath` — источники формирования ссылок. Не собирать языковые URL вручную в компонентах. Root fallback 404 статический и англоязычный; локализованные страницы доступны через языки. Выбор локализованного HTTP fallback при публикации зависит от настройки хостинга.

Портфолио CRM/ERP использует `pathFor(locale, 'portfolio', slug)`: шапка и подвал сохраняют slug при смене языка. CRM включает Hero с двухцветным заголовком, тегами Next.js / Prisma / PostgreSQL / AI, двумя внешними CTA и иллюстративным HTML-макетом воронки; ниже шесть FeatureCard в bento-сетке (таск 2), интерактивный workflow из пяти этапов (таск 3), демо-доступ, шесть дополнительных модулей и нижний CTA (таск 4). На desktop Hero двухколоночный, до 960px — вертикальный; сетки карточек перестраиваются из трёх колонок в две, до 640px — в одну. Workflow: Лид → Контакт → Сделка → Автоматизация → Аналитика; SVG-узлы идут в ряд, до 640px — вертикально. Демо-доступ расположен справа от описания этапа, до 960px — под ним. ERP включает Hero с HTML-превью, тегами Next.js / PostgreSQL / Docker / Prisma и Hub & Spoke-схемой (таск 5): ERP Core и шесть модулей с подсказками и аккордеоном. После схемы расположены семь карточек ERP-модулей с описаниями и списками возможностей и нижний CTA на демо/GitHub (таск 6). Якоря — `erp-modules` и `erp-demo`. Сетка 3 / 2 / 1 колонка при тех же порогах 960/640px; «Настройки» занимают последнюю широкую строку. Ссылки главной и SEO завершены в таске 7; общий `BaseLayout` сохраняет noindex.

Якоря главной сохранены: `top`, `services`, `demo-projects`, `examples`, `people-documents`, `business-systems`, `planning-analytics`, `workflow`, `value`, `approach`, `faq`, `contact`. Внутренняя навигация направляет к этим якорям нужной языковой главной.

`examples` теперь находится на контейнере hero. Три тематических якоря относятся к примерам внутри него. С таска 7 кнопка All-in-one CRM ведёт на локализованный `/portfolio/crm/`, ссылка разбора ERP — на `/portfolio/erp/`; `business-systems` сохранён. Остальные четыре разбора и все пять ссылок демо-сценария остаются прежними. URL задаются через `projectHref` / `allInOne.href` в `demo-projects.ts` и `pathFor`. `workflow` оставлен как совместимый якорь начала hero после удаления отдельного маршрута. Второй CTA hero открывает существующее локальное демо. Порядок секций: hero → направления → шесть демо-проектов → эффект → как начать → FAQ → бриф.

Демо принимает только пять известных slug в `?step=`. Неизвестный параметр открывает первый шаг. Это точка входа в локальную симуляцию, не сохранённая пользовательская сессия. Изменение сценария и кнопка сброса начинают маршрут заново.

## 6. Состояния и доступность

- Одна h1, один main, одна шапка и один подвал на каждой странице. Сохранять skip-link и локализованный html lang.
- Ссылки и кнопки получают видимый зелёный focus ring. Поля имеют реальные label. Кнопки сохранения и демо используют настоящие button.
- Декоративные иконки имеют пустой alt/aria-hidden. У таблиц есть заголовки строк и колонок. Интерфейсные превью — иллюстрации, не неработающие формы.
- Состояния демо объясняются текстом и маркерами, а не одним цветом. Текущий шаг отражается через aria-current; статус — role=status.
- `[hidden]` обязательно скрывает элементы даже при display:inline-flex у кнопки. Нельзя одновременно показывать Next и Review.
- Нативный popover поддерживает Escape, переключение и закрытие после навигации. Слушатели не накапливаются при Astro ClientRouter.
- Колода начинается с обложки; hover или клавиатурный фокус раскрывает веер. Первый клик увеличивает карту, повторный переворачивает. Доступны возврат на лицевую сторону, закрытие, Escape и touch-кнопки выбора модуля. Ссылки проекта/демо и кнопки управления не запускают общий обработчик переворота; скрытые стороны исключаются из фокуса через `inert`/`aria-hidden`. `prefers-reduced-motion` отключает переходы, а слушатели очищаются при смене страниц Astro.
- FAQ остаётся нативным details/summary. При reduced-motion анимации и переходы ограничены.
- CRM workflow использует tablist/tab/tabpanel с roving tabindex. Стрелки, Home/End и Space управляют этапами; до 640px используются стрелки вверх/вниз. Автопереход раз в 4000ms начинается при видимости секции, сбрасывается при выборе этапа и имеет кнопку паузы. Таймер остановлен вне viewport, при скрытой вкладке, клавиатурной работе и reduced motion. Автопереход не перемещает фокус и не запускает live-объявления. Без JavaScript узлы остаются ссылками на все пять видимых описаний. GSAP, observers, таймер и локальные слушатели очищаются при переходах Astro/pagehide.
- Демо-доступ CRM берётся из `crmDemoCredentials`: `admin@demo.com` / `admin123` — предоставленная владельцем публичная учётная запись демо. Значения видны в readonly-полях с label. Две кнопки вызывают Clipboard API и объявляют локализованный результат через role=status. При отказе/отсутствии API поле получает фокус и выделение для ручного копирования; ложное сообщение об успехе не показывается. Без JS кнопки скрыты, поля доступны для выделения. AbortController очищает локальные listeners, асинхронные завершения после ухода не меняют DOM.
- ERP Hub: фокус/hover показывает читаемую и hoverable tooltip-карточку, Escape закрывает её без перемещения фокуса. Клик/Enter/Space открывает один модуль в аккордеоне; повторный выбор закрывает его, ручной summary синхронизирует aria-expanded узла. Touch открывает панель с первого нажатия без промежуточного tooltip. Без JS узлы остаются ссылками к native details. GSAP hover увеличивает узел до 1.05; reduced motion отключает увеличение, fade и точки потока. У потока есть пауза, а вне viewport/в скрытой вкладке он приостановлен. Все локальные listeners, observers, timeout и GSAP-контексты очищаются при Astro/pagehide.
- При отключённом JavaScript бриф и демо содержат пояснение. Проверка этого режима в отдельном браузере пока не выполнена.

Измеренный контраст: основной текст 18.28:1, вторичный 6.02:1, белый текст основной кнопки 4.69:1, граница поля 3.29:1, текст состояния остановки 7.59:1, завершения 13.75:1. Это проверка перечисленных пар, не полная сертификация доступности.

## 7. Данные и пределы функциональности

Имена Cherryli, Budget, Aprobery, ERP, Steer применены к демонстрационным модулям. Превью показывают условные записи, бюджеты и события. Нельзя выдавать их за реальные клиентские внедрения, измеренные результаты или активные ERP-интеграции.

По запросу владельца денежные значения отображаются в тысячах евро; обозначения рублей не используются. Hero: «Выручка, тыс. €» / «Revenue, € thousands» / «Venituri, mii €». Budget и ERP сохраняют суммы, используя локальный формат: `24 тыс. €`, `€24k`, `24 mii €`; дробные значения используют локальный десятичный разделитель. Графики hero показывают иллюстративную динамику выручки 72–178 тыс. €, доли сделок 45/30/15/10% и условное сравнение четырёх команд. Доступные подписи прямо указывают демонстрационную природу данных. Названия, тексты, ссылки и поведение шести карточек при этой итерации сохранены.

Бриф создаёт файл на устройстве, не отправляет сведения в Optimix. Демо работает локально и не выполняет настоящую закупку. Существующие описания этих возможностей сохранены. Подключение канала обращений и юридической политики не входило в миграцию дизайна.

Сайт остаётся noindex. Не менять этот статус без готового канала обращения, подтверждённой политики и решения о публикации. CRM/ERP имеют локализованные title/description, canonical, og:title/description/type/locale/url/site_name и Twitter summary/title/description. Отдельного social preview нет, og:image не подменяется случайным активом. Canonical и hreflang используют PUBLIC_SITE_URL, при его отсутствии — документированный production origin `https://opti-mix-three.vercel.app` из astro.config.mjs, никогда localhost. Hreflang включает EN/RO/RU и x-default на английский маршрут.

## 11. Обязательный публичный демо-доступ по ролям

Для портфолио с парольным входом данные учебных пользователей должны быть открыты на карточке и странице проекта: роль, логин, пароль видимым текстом, отдельное копирование каждого поля. Это прямое правило владельца, распространяющееся и на будущие продукты. Источник — `src/content/demo-access.ts`: три CRM-аккаунта и шесть ERP-аккаунтов из опубликованной учебной документации/seed. Каждый CatalogSlug имеет явный режим `accounts`, `none` или `chatgpt`; accounts без опубликованных пользователей приводит к ошибке сборки. Никогда не брать значения из .env, рабочих аккаунтов, owner key файлов или провайдерских секретов.

`DemoAccess.astro` повторно используется на карточках главной и каталога и на страницах. `demo-access.ts` (script) поддерживает несколько блоков на странице, выбор роли, Clipboard API, ручное выделение при отказе, корректные status-сообщения, отмену устаревшего сообщения при смене роли и Astro/pagehide/bfcache cleanup. Пароли — readonly type=text, всегда видны. Без JS доступен native details со всеми аккаунтами и ручным копированием. Старый CrmDemoAccess теперь обёртка общего компонента.

Контролы и текст внутри data-demo-access исключены из общего обработчика переворота колоды. Слой, угол, масштаб и hover остаются прежними. Только раскрытая карта с реквизитами получает дополнительную высоту (840px desktop / 910px mobile); закрытые физические слои не меняются. На мобильном роли и поля помещаются без переполнения.

PDF: ручные правки не требуют аккаунта. Commerce/Founder/Recruiting сейчас используют персональный вход ChatGPT, общего пароля для него нет; отображается способ входа, а не вымышленные данные. Владелец отдельно сделает эти демо публичными и добавит README.

Подтверждены копирование 18 полей всех девяти пользователей, fallback, смена роли во время копирования, очистка после Astro-перехода, локали и no-JS. Доказательства — `docs/portfolio-release-2026-10-29/demo-access-qa/`, сценарий `experiments/verify-demo-access.mjs`. Внешний ERP-вход продаж успешно проверен; вход аналитика не подтвердился.
